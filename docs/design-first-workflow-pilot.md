# Sloppertizer design-first WorkFlow experiment

## Thesis
Instead of CSS-polishing the original Lovable website, rebuild its public React route with an original editorial layout and an honest illustrative workspace. Preserve the app's protected routes, navigation to auth and responsible AI, core documented feature categories and user interactions.

## Scope
Pinned upstream: TinyikoMamban/workflowai-pro at 1ab6e6fba96ad6cadec64bfa9132398313b40986. MIT licensed. Apply these exact files to upstream:

- pilots/workflow-design-first/index.tsx → src/routes/index.tsx
- pilots/workflow-design-first/sloppertizer-pilot.css → src/routes/sloppertizer-pilot.css

This is **human-directed experimental code**, NOT automatically learned or generated by the Sloppertizer engine. No existing pages are deployed or replaced. It establishes a quality reference for possible future automation.

## Source truth
The upstream code contains six distinct tools: email drafting, meeting-note processing, task planning, research, chat and a prompt library. The authenticated meeting and research pages contain mock structured-result logic. The original landing also contains hardcoded stats and customer testimonials, which this pilot deliberately omits pending independent verification.

The interactive three-tab workspace is **explicitly labelled as illustrative**; its fields and outlines communicate feature categories without pretending to display real user data, completed AI results or a screenshot of the current app. No fake performance statistics, testimonial photos or endorsements were introduced.

## Art direction
Warm-paper editorial layout, deep forest workbench, spare type, concrete content hierarchy, source-backed iconography, 6-part capability index, a high-contrast accessibility-first FAQ and original navigation. No gradients, glass defaults, generic card grids, fabricated claims, remote fonts or image-model assets.

## Acceptance
Successful TanStack app build, original /auth and /responsible-ai links, six feature descriptions, interactive preview tabs with keyboard navigation, mobile navigation, FAQ, desktop/mobile Chromium screenshots, zero runtime errors/overflow/broken images/new text collisions/axe contrast failures. Require human aesthetic approval before showing as premium.

Source: .github/workflows/design-first-workflow.yml. This is an isolated proof, **not** a product deployment.

## Design review and remaining limits

The redesign replaces the original generic gradient hero and hardcoded impact mockup with a distinct editorial hierarchy, capability index, and interactive concept. Its non-backend demonstration is labelled as illustrative. The real product's authenticated routes are untouched, but their backend behavior was not tested in this run.

Do not call this a measured 8/10 or 10/10 result: it still needs independent human taste review, and its product preview could be replaced with actual product evidence. The pilot is **manually authored**, not an autonomous Sloppertizer output. Turning the successful design decisions into reusable, source-grounded engine operations is the next development step.
